# Audit 003: Auth Pages

## Status

Audit only. No implementation changes made pending approval of findings.

## Findings

1. **HIGH - Login form absent.** `/masuk` only explains invitation-only access; email/password inputs, submission, validation, loading, error, and success states are missing. (PRD Task 1.4, R-26, R-27)

2. **HIGH - Invitation activation route absent.** `/undangan/[token]` does not exist; invitees cannot enter business name, password, or subscription plan. (PRD Task 1.4, R-26, R-27)

3. **MEDIUM - Login page uses a dead-end CTA.** “Hubungi tim SnapArcade” links to contact, but does not serve login or invitation activation. The form should provide the relevant invitation path without implying self-registration. (R-24, R-26)

4. **MEDIUM - Auth UI has no simulated result states.** The requested dummy implementation needs visible loading, error, and success feedback without claiming real authentication or sending credentials. (PRD Task 1.4, R-27, R-38)

## Direction

Use the PRD's existing public-area direction: Neobrutalism, yellow/cyan/pink/lime palette, Space Grotesk headings, bold black borders, hard shadows, and responsive layouts. Existing tokens and `.nb-card`, `.nb-button`, `.nb-input` are already defined.
