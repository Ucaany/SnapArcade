## Font Follow-up (2026-09-28)

User reported fonts did not match the documented direction. Root cause found at runtime:

8. **RESOLVED, MEDIUM, R-06/R-35**: `next/font` CSS variables (`--font-inter-loaded`, `--font-space-grotesk-loaded`, `--font-archivo-black-loaded`) were attached to `<body>`, while the `@theme` font variables (`--font-inter`, `--font-space-grotesk`, `--font-archivo-black`) were declared at `:root` referencing those body-scoped variables. Custom property substitution happens at the declaring element (`:root`), where the loaded variables did not exist, so every font declaration resolved as invalid and the whole site fell back to the UA default serif. Additionally, `.public-theme` overrode the display font variables to a single body font. Fixes: variables moved to `<html>`, the `.public-theme` display-font overrides removed, public body standardized on Inter with Space Grotesk headings and Archivo Black display accents, logo and auth headings moved to Space Grotesk, and the unused DM Sans load removed.

Rendered-font evidence on the production build (`npm start`):

- `/` h1 and logo: `Space Grotesk`.
- `/` pricing and feature marks: `Archivo Black`.
- `/` body copy, `/kontak` labels: `Inter`.
- `/masuk` h1: `Space Grotesk`.
- Console errors: 0. All 9 public routes: HTTP 200. Mobile 390px: no horizontal overflow; menu opens and closes. `npm run build` PASS, `npm run typecheck` PASS.
